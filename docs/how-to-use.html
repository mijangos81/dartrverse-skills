dartRverse · skill v2.0.0

dartR Function Review

Claude reviews one function.
You approve each change.
Nothing changes without you.

Team member

run a review
1 · Install once

Get the skill

git clone https://github.com/mijangos81/dartrverse-skills.git
ln -s "$(pwd)/dartrverse-skills/skills/dartr-function-review" ~/.claude/skills/
↓
2 · Start

Ask Claude Code

review gl.report.callrate

Open Claude Code in the package folder, on your dev_<name> branch. The skill claims the function for you in the manifest. Two people cannot claim one function.

The manifest is function-review/manifest.csv in the package repository: one row per function — who reviews it, and its status (in-review → awaiting-approval → pr-open → done). It shows campaign progress at a glance.

↓
3 · Claude reviews · read-only

Claude finds the problems

It saves the current behaviour as a test. It checks the code against the team rules and the docs. It writes a report to function-review/reports/. It does not change the code.

↓
4 · You decide

Tick the changes you approve

You get a findings table and clickable boxes. Tick a box to approve a change. Or type: “apply 1 and 3, defer the rest”. Changes that alter results get their own box.

↓
5 · Claude applies

Only approved changes go in

The baseline test runs again. Each difference must match an approved change. If not, Claude stops and reports.

↓
6 · You decide

OK the commit

Claude shows the commit message and the pull request title. Nothing is pushed until you say OK. Then: one pull request per function, to dev, with the report linked.

Custodian

close the loop
7 · Merge

Review and merge the pull request

Each pull request has one function, its report, and its regression test. Merge to dev. The manifest row becomes done.
